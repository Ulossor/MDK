Архитектура данных в Python: ORM, N+1 и Паттерны

Как работают ORM (SQLAlchemy, Django ORM)?

ORM (Object-Relational Mapping) — это прослойка между кодом и базой данных. Она превращает таблицы базы данных в классы Python, а строки в таблицах — в объекты этих классов.

  • Вы пишете код на Python, а ORM сама генерирует SQL-запросы.
  • Django ORM тесно связана с фреймворком Django и работает по принципу "всё включено".
  • SQLAlchemy — это отдельная мощная библиотека, которая разделена на Core (низкоуровневая работа с SQL) и ORM (маппинг объектов).

Что такое маппинг объектов и альтернативы

Маппинг — это правило связи полей класса Python с колонками в таблице SQL (например, атрибут name связан с колонкой user_name).

Альтернативы ORM:

  • Сырые SQL-запросы (Raw SQL): Вы сами пишете строки с SQL-кодом (через psycopg2 или sqlite3). Максимальная скорость, но много рутины и риск SQL-инъекций.
  • Query Builders (Построители запросов): Инструменты вроде PyPika или Core-часть SQLAlchemy. Позволяют собирать SQL из методов Python без создания тяжелых объектов-моделей.

Проблема N+1 запросов: что это и как диагностировать

Проблема N+1 возникает, когда программа делает 1 запрос на получение списка основных объектов, а затем ещё N запросов (по одному на каждый объект) для получения связанных данных.

Пример: У вас есть 10 авторов. Вы получили их список (1 запрос). Потом в цикле выводите книги каждого автора (ещё 10 запросов). Итог: 11 запросов вместо одного с JOIN.

Как диагностировать:

  • Включить логирование SQL-запросов (в Django — django.db.connection.queries, в SQLAlchemy — echo=True).
  • Использовать инструменты мониторинга (например, Django Debug Toolbar). Следить за резким ростом числа одинаковых запросов.

Методы решения проблемы N+1 в Python

Для решения используют жадную загрузку (Eager Loading) — данные подтягиваются сразу в одном запросе.

  • JOIN (joinedload): Загружает связанные данные через SQL-оператор JOIN. Хорошо для связей "один к одному" или "многие к одному".
  • Select-in (selectinload в SQLAlchemy / prefetch_related в Django): Делает второй отдельный запрос с оператором IN (...) для загрузки связанных коллекций. Отлично подходит для связей "один ко многим".

Паттерны Репозиторий (Repository) и Единица работы (Unit of Work)

Эти паттерны помогают отделить логику работы с базой данных от бизнес-логики приложения.

  • Репозиторий (Repository): Класс-посредник, который имитирует коллекцию объектов в памяти. Скрывает детали SQL (методы вроде repo.get_by_id(5) или repo.save(user)).
  • Единица работы (Unit of Work - UoW): Паттерн, который следит за всеми изменениями объектов в рамках одной транзакции. Он гарантирует, что либо всё сохранится в базу (коммит), либо всё отменится (откат/rollback) при ошибке.
